# CRM для сайта «Сибирь-Оптика»

Это MVP-версия CRM для сайта-витрины без интернет-магазина, оплаты и доставки.

## Что умеет

- принимать заявки с сайта
- принимать предварительную бронь очков
- принимать запись на проверку зрения
- показывать заявки в CRM
- менять статусы заявок
- вести заметки сотрудника
- экспортировать заявки в CSV
- редактировать каталог товаров и услуг
- скрывать товары с сайта
- показывать счётчик необработанных заявок
- хранить данные в PostgreSQL при наличии `DATABASE_URL`
- автоматически переносить данные из `data/leads.json`, `data/products.json`, `data/settings.json` в PostgreSQL при первом запуске

## Как запустить локально без PostgreSQL

Этот режим оставлен как запасной. Если `DATABASE_URL` не задан, сайт продолжит работать через JSON-файлы.

```bash
npm install
npm start
```

Сайт:

```text
http://localhost:3000
```

CRM:

```text
http://localhost:3000/crm
```

Пароль по умолчанию:

```text
admin12345
```

## Как запустить с PostgreSQL

Сначала нужно создать базу данных PostgreSQL, например:

```sql
CREATE DATABASE sibir_optika;
```

Потом создать файл `.env` рядом с `server.js`:

```text
PORT=3000
ADMIN_PASSWORD=admin12345
DATABASE_URL=postgres://postgres:postgres@localhost:5432/sibir_optika
DATABASE_SSL=false
```

В `DATABASE_URL` нужно заменить логин, пароль, хост, порт и название базы на свои.

После этого выполнить:

```bash
npm install
npm start
```

При первом запуске сервер сам создаст таблицы:

```text
leads
products
settings
```

Если таблицы пустые, данные автоматически перенесутся из:

```text
data/leads.json
data/products.json
data/settings.json
```

После успешного запуска в терминале будет видно:

```text
Хранилище данных: postgres
```

Если написано:

```text
Хранилище данных: json
```

значит `DATABASE_URL` не задан или `.env` не подхватился.

## Что теперь хранится в PostgreSQL

Заявки хранятся в понятной таблице `leads` с отдельными колонками:

```text
id, status, type, name, phone, service, product_title, page, source, created_at, updated_at
```

Каталог товаров хранится в понятной таблице `products` с отдельными колонками:

```text
id, section, title, category, brand, type, price, availability, active, sort
```

Настройки сайта хранятся в таблице `settings`.

JSON-файлы остаются в проекте как стартовые данные и резервный вариант, но при включённом `DATABASE_URL` рабочим хранилищем становится PostgreSQL.


## Как проверить заявки в pgAdmin

В pgAdmin можно открыть обычную таблицу:

```text
sibir_optika → Schemas → public → Tables → leads → View/Edit Data → All Rows
```

Теперь заявка будет отображаться не одной большой JSON-ячейкой, а нормальными колонками: имя, телефон, статус, тип, услуга, товар, страница, источник и даты.

Если раньше таблица `leads` уже была создана в старом JSON-формате, при следующем запуске проекта она будет автоматически перенесена в новый понятный формат. Старая техническая таблица будет сохранена как `leads_json_backup`.

## Как поменять пароль CRM

В `.env`:

```text
ADMIN_PASSWORD=новый_пароль
```

После изменения перезапустить сервер:

```bash
npm start
```

## Резервное копирование PostgreSQL

Для рабочей версии нужно делать резервную копию базы. Пример команды:

```bash
pg_dump "postgres://postgres:postgres@localhost:5432/sibir_optika" > backup_sibir_optika.sql
```

В рабочем запуске пароль и адрес базы нужно заменить на реальные.

## Обновление: сайт без общей витрины товаров

Клиентская часть сайта теперь не показывает общий список товаров. Основной акцент сделан на услуге мастерской: изготовление очков, установка и замена линз, подгонка и ремонт.

Каталог товаров сохранён в CRM. Через раздел «Каталог» можно добавлять реальные товары, которые есть в наличии, указывать цену, наличие, описание и фото. Эти данные хранятся в базе и могут использоваться для внутреннего учёта, заявок и будущего вывода на сайт, если витрину снова потребуется включить.

Фото товара загружается в CRM через поле «Фото товара». Файлы сохраняются в папку `public/uploads/products`, а ссылка записывается в карточку товара.
